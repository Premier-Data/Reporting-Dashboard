# Implementation Plan — Soccer JSON adapter keys the comparison stat on `statTypeName`

## Context & decisions (grounded in the code I read)

- All edits happen in the worktree app: `c:\Users\AndyDin\reporting-dashboard\.worktrees\json-stat-name\reporting-ui`. Use absolute paths. Never touch the sibling checkout at `c:\Users\AndyDin\reporting-dashboard\reporting-ui`.
- The file to change is `lib/comparison/json-adapter.ts`. `jsonEventsToInstances` (~line 232) builds each `Instance.stat` via `opts.mapStatName ?? defaultMapStatName(ev.statTypeName, ev.statTypeCode)` (~line 246). The comparison engine (`xml-compare.ts`), the by-stat / by-category timeline, and the accuracy breakdown all read `Instance.stat`, so changing `defaultMapStatName` changes the timeline/stat and the matching key together — exactly what the user asked for.
- **Decision — invert `defaultMapStatName` to name-primary.** The canonical stat becomes the trimmed `statTypeName`, falling back to the code-derived label (`STAT_CODE_MAP` then `deCamel(code)`) only when `statTypeName` is missing/empty. Rationale: the user's checks are JSON-vs-JSON from one platform, so both sides carry the same `statTypeName` and pair on it; coarser granularity (several codes sharing one name, e.g. `ShortPassEffective`/`ShortPassIneffective` → "Pass") is intended.
- **Decision — leave `defaultMapCategory` code-driven; do NOT change `classifyCategory` regexes.** `defaultMapCategory(statTypeCode, mappedStat)` still looks up `STAT_CODE_MAP[code].category` first, so when a code is present (the real feeds) categories stay correct even though the stat is now a name. I verified the fallback path too: classifying each `statTypeName` in the fixture (`pd-819-34131-AI.json`) with the current `classifyCategory` buckets them sensibly (shot→Shots, keeper→Goal Keeper, pass/cross/carry/touch→Passing, corner/throw in/kick off→Event, everything else→General Play). No name-based label misbuckets, so no regex change is warranted. (If the implementer finds a real feed name that misbuckets, adjust a `classifyCategory` regex only for that case and add a test; do not regress existing grouping.)
- **Decision — keep `STAT_CODE_MAP` and `CANONICAL_TO_NATIVE`.** They remain the name-empty fallback and the category source; the round-trip export still uses `CANONICAL_TO_NATIVE`.
- **Scope confirmation.** This adapter is the single JSON path for both master and analyst sides (callers: `app/accuracy-compare/page.tsx`, `lib/api/accuracyChecks.ts`, `app/accuracy-checks/page.tsx`, `app/disputes/page.tsx`). AFL is NOT on this path — AFL uses XML through `afl-player-accuracy.ts`. No AFL behavior changes.
- **Mixed XML-master-vs-JSON-analyst re-baseline.** The only test exercising a JSON analyst against an XML master is `lib/comparison/json-adapter.test.ts` (Chester/Merthyr). Name-keying intentionally loosens that pairing (name "Pass" no longer equals the XML's "Short Passes Successful"), so the `defaultMapStatName` unit assertions and the paired-count assertion in that file WILL change. Per the user directive the NEW default is name-based, so those tests get RE-BASELINED (with a comment), not reverted.
- **Next.js rule.** `AGENTS.md` requires reading the matching guide under `node_modules/next/dist/docs/` before any Next.js API. This change is pure TypeScript in the comparison lib with no Next.js API surface, so no guide applies; rule acknowledged.
