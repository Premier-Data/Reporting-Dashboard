- [ ] 4. In the same `lib/api/accuracyChecks.ts`, implement `renameMaster(oldFileName, newFileName): Promise<RenameMasterResult>` and `deleteMaster(fileName, deletedBy?: string | null): Promise<DeleteMasterResult>` exactly per the design. `renameMaster`: compute `next = normalizeMasterName(newFileName)`; if `!isValidMasterName(next)` throw `"Master name cannot be empty."` (pre-DB, no write); `groupIds = await resolveActiveGroupIds(oldFileName)`; if empty return `{ updated: 0 }`; collision check by id-set membership — unless the whole group is a pure case/whitespace self-rename (`sameMasterName(next, oldFileName)` already true), query `.select("id, file_name_master").is("deleted_at", null).ilike("file_name_master", next)` and if any returned row `r` has `sameMasterName(r.file_name_master, next)` AND `r.id ∉ groupIds` throw `A master named "<next>" already exists. Choose a different name.`; then `update({ file_name_master: next }).in("id", groupIds).select("id")` and return `{ updated: rows.length }`. JSDoc must state the collision guard is best-effort (TOCTOU; no DB unique constraint; out of scope). `deleteMaster`: `ids = await resolveActiveGroupIds(fileName)`; `ids.length === 0` → return `{ deleted: 0 }`; `ids.length > 1` → throw `Cannot delete: ${ids.length} accuracy checks are attached to this master. Replace it instead.`; exactly one → `update({ deleted_at: new Date().toISOString(), deleted_by: deletedBy ?? null }).eq("id", ids[0])` and return `{ deleted: 1 }`. Any Supabase error → `console.error` + throw `error.message || "Failed to rename master."` / `"Failed to delete master."`.

## Notes / assumptions

- Item ordering is dependency-driven: the pure module (1) and its tests (2) come first because the data layer (3-4) and dialog (5) import from it; the dialog (5) before page wiring (6) because the page imports the dialog; final verification (7) after all code lands; manual DB checks (8) last.
- Each of items 1-6 leaves the tree buildable on its own (new exports/components are additive; the dropdown and existing flows are untouched until item 6 wires the gated button).
- The three design-review NITs are non-blocking and folded in: NIT 1 (ILIKE over-match wording) in item 3; NIT 2 (dropdown key/value note — already correct, no code change) needs no action; NIT 3 (empty-master guard pinned to the Replace handler) in item 5.
- RLS on `accuracy_checks` is the intended authoritative gate but lives in Supabase, not this repo, so it could not be verified here; the `canManageMasters` role check is a UX gate consistent with the existing `canEditMaster`/`canResolveDispute` features. The `deleteMaster` DB-side group re-check is the data-safety guard.
- The rename collision guard is best-effort (TOCTOU; no DB unique constraint — out of scope); the next `getSavedMasters()` refresh surfaces any duplicate.
